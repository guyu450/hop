原生的Microsoft SQL JDBC驱动程序附带了额外的文件，可使用当前的MS Windows凭据进行身份验证。当你从Microsoft网站下载JDBC驱动程序并解压后，会有如下目录结构：

sqljdbc_11.2\enu\auth\x64 â†? 64位身份验证支持文件。

复制Microsoft身份验证dll文件：
源路径： sqljdbc_11.2\enu\auth\x64\mssql-jdbc_auth-11.2.3.x64.dll
目标路径： hfxt\lib\mssql-jdbc_auth-11.2.3.x64.dll
以及你的Java安装文件夹，以我的为例：
C:\Program Files\Microsoft\jdk-17.0.6.10-hotspot\bin
C:\Program Files\Microsoft\jdk-17.0.6.10-hotspot\lib

复制JDBC驱动程序：
源路径： sqljdbc_11.2\enu\mssql-jdbc-11.2.3.jre11.jar
目标路径： \hfxt\plugins\databases\mssqlnative\lib，替换已有的任何版本。

  • 要连接到SQL Server，首先安装任何必要的JDBC驱动程序（请参阅Hfxt安装文档）

通过TCP/IP连接到原生SQL Server的故障排除

https://stackoverflow.com/questions/18841744/jdbc-connection-failed-error-tcp-ip-connection-to-host-failed

打开SQL Server配置管理器并设置TCP/IP和端口1433

  • 打开SQL Server配置管理器，然后展开”SQL Server网络配置”。

  • 点击”实例名称的协议”，然后确保右面板中的TCP/IP已启用，并双击TCP/IP。

  • 在”协议”选项卡上，注意”全部侦听”项的值。

  • 点击”IP地址”选项卡（如下所示图像）：如果”全部侦听”的值为”是”，则此SQL Server实例的TCP/IP端口号是”IPAll”下”TCP动态端口”项的值。如果”全部侦听”的值为”否”，则此SQL Server实例的TCP/IP端口号是特定IP地址的”TCP动态端口”项的值。

  • 确保TCP端口为1433，点击”确定”

  • 进行任何更改或新设置后，必须重新启动SQLSERVER服务

  • 如果你看到Windows SQL Server / SQL Server浏览器 / SQL Server代理服务状态为”已停止”，右键单击SQL Server / SQL Server浏览器，然后点击”启动”。

  • 我经常使用的一个好方法是使用telnet，例如在Windows命令提示符下运行：telnet 127.0.0.1 1433

    • 如果你得到一个空白屏幕，则表示网络连接已成功建立，这不是网络问题。如果你得到”无法打开到主机的连接”，那么这就是网络问题

  • 或者，你可以使用netstat -a查找打开并正在监听的端口

    • netstat -ab | find "1433"

    • netstat -abn |Select-String -Pattern sql -Context 0,1

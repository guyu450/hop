建立雪花（Snowflake）SSL 认证连接

简介

本简短指南将引导我们创建一个雪花（Snowflake）用户，该用户配置为附加公钥的服务账户，并配置 Hfxt，以便它能够使用私钥、角色、计算资源等进行连接，从而开展进一步的工作。

在雪花（Snowflake）中创建 RSA 密钥对和 Hfxt 服务用户

首先，您应该为要在连接雪花（Snowflake）时与 Hfxt 一起使用的服务用户创建一个 RSA 密钥对。

您可以在大多数 Linux / WSL（适用于 Linux 的 Windows 子系统）上通过在终端窗口中运行以下命令来生成 RSA 密钥对。

openssl rsa -in rsa_key.p8 -pubout -out rsa_key.pub

然后，rsa_key.pub 文件的内容将用于雪花（Snowflake）的 CREATE USER 语句中。

USE ROLE SECURITYADMIN;

CREATE USER SVC_ETL_HFXT_USER_TEST
    DEFAULT_WAREHOUSE = ING_DEV_WH
    DEFAULT_NAMESPACE = DB_DEV
    DEFAULT_ROLE = SVC_ETL_DEV_ROLE
    TYPE = SERVICE
    RSA_PUBLIC_KEY = 'public key copy paste in single quotes'
    COMMENT = 'Test ETL service user';

在屏幕截图中，我们可以定义希望用户具备的所有属性，包括要使用的默认计算资源（仓库）、命名空间（数据库）和角色。我们还定义了一个特殊属性 TYPE = SERVICE，以确保该用户无法使用登录页面登录，只能通过编程方式登录。

下载雪花（Snowflake）JDBC 驱动程序和加密库

下载 最新的雪花（Snowflake）JDBC 驱动程序。文件名的命名模式为 snowflake-jdbc-3.19.0.jar

为了支持基于证书的身份验证，我们还需要从著名的 Java 加密 API 库提供商 Bouncy Castle 下载 两个 jar 文件。

第一个是提供程序 jar 文件，其名称表明了支持的 JRE/JDK 版本。请确保下载与您的 JDK 版本以及 Hfxt 所需版本相匹配的正确版本。第一个要下载的文件是 bcprov-jdk<VERSION>.jar

其次，我们需要加密库，其文件名中也包含 JDK 版本支持信息。文件名是 bcpkix-jdk<version>.jar

JDBC 驱动程序和两个 Bouncy Castle 加密库 jar 文件需要放入 hfxt/lib/jdbc 目录中。请务必删除在 hfxt/lib/jdbc 中找到的任何旧版本的雪花（Snowflake）JDBC 驱动程序 jar 文件。雪花（Snowflake）驱动程序维护良好且经常更新。

将 RSA 私钥放置在 Hfxt 的文件夹中

私钥文件必须存储在 Hfxt 的根文件夹中。

除了 Hfxt 根文件夹之外，可能还有其他方法可以包含私钥（例如在连接的 选项 选项卡中定义），但目前尚不清楚。

收集雪花（Snowflake）连接属性

让我们先看最终结果，然后再描述每个属性的来源和原因。

Hfxt 中的大多数连接使用典型字段，如 服务器主机名、端口号、仓库、数据库名称，但由于这是一个更高级的连接配置，我们需要利用可以在下面显示的 选项 选项卡上设置的额外 JDBC 参数。

查看 选项 选项卡，我们使用了几个关键字，

authenticator、private_key_file、role、schema 和 user。这些参数来自雪花（Snowflake）JDBC 参数文档网站。

我们首先告诉 JDBC 驱动程序我们将使用 snowflake_jwt 进行身份验证，这意味着它将期望看到某种私钥和公钥。

在这种情况下，使用 private_key_file 参数。例如，这可能来自 AWS 秘密存储中的证书。在这种情况下，证书或密钥文件不必留在环境中，并且在镜像消失时会被处理掉。其他变量允许您对其进行编码（BASE64）等操作。

服务器主机名的 URL 可以通过在雪花（Snowflake）控制台左下角点击您的名字，选择您的实例，然后有一个小链接图标来获取。当您将此粘贴到 Hfxt 的对话框中时，去掉 HTTPS:// 部分，因为它不是必需的。连接始终是加密的。

用户界面

在大多数情况下，Neo4j 驱动程序 可以自动确定协议和安全选项，让您能够专注于最基本的选项：服务器、端口、用户名和密码。和往常一样，我们建议您切勿硬编码任何设置，而是使用可以在环境配置文件中定义的环境变量。这样，同一个Neo4j连接可以在多个环境中使用，而无需更改管道或工作流。

高级选项

连接活跃性检查超时时间（毫秒）

在连接池中闲置时间超过此超时时间的池化连接，在再次使用之前将进行测试，以确保它们仍然可用。如果此选项设置得过低，获取连接时将产生额外的网络调用，从而导致性能下降。

如果设置得过高，您可能会收到由不再活跃的连接支持的会话，这将导致应用程序出现异常。假设数据库正在运行，如果您重试获取会话，这些异常将会消失。

因此，此参数用于在应用程序遇到连接问题的可能性和性能之间进行权衡。

通常情况下，您无需调整此参数。默认情况下不进行连接活跃性检查。值为0表示将始终测试连接的有效性，负值表示永远不会测试连接。

最大连接生存期（毫秒）

超过此阈值的池化连接将被关闭并从连接池中移除。这种丢弃操作在获取连接时进行，以确保新会话永远不会由旧连接支持。将此选项设置为较低的值将导致较高的连接更替率，并可能导致性能下降。

建议将最大生存期设置为略小于网络设备（负载均衡器、代理、防火墙等也可能限制最大连接生存期）中配置的值。

此设置也可以与连接活跃性检查超时时间（毫秒）值结合使用。在这种情况下，建议将活跃性检查设置为小于网络设备设置的值，并将最大生存期设置为一个合理的较大值，以便偶尔”更新”连接。

默认的最大连接生存期为1小时。值为零和负数将导致不检查生存期。

最大池大小

配置到单个数据库的连接池中连接的最大数量。当在为”bolt”方案的URI创建的直接驱动程序中使用时，此设置限制连接池中的连接总数。当在为”neo4j”方案的URI创建的路由驱动程序中使用时，它将限制每个集群成员的连接数量。

当达到限制时，将最多尝试配置的超时时间”连接获取超时时间（毫秒）“来获取连接。

默认值为100。允许负值，这将导致池大小无限制。不允许值为0。

连接获取时间（毫秒）

配置连接获取操作从连接池中获取连接的最长尝试时间。只有当所有现有连接都在使用且由于达到最大连接池大小而无法创建新连接时，此超时才会生效。如果在配置的时间内无法获取连接，将抛出错误。

默认值为60秒。允许负值，这将导致获取超时无限制。允许值为0，这将导致无超时，并且在连接不可用时立即失败。

最大事务重试时间（毫秒）

指定通过会话读和写事务允许事务重试的最长时间。这些方法将在出现ServiceUnavailableException、SessionExpiredException和TransientException时，使用1秒的初始延迟以指数退避的方式重试给定的工作单元。默认值为30秒。

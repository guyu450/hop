执行信息存储位置

描述

执行信息存储位置决定了 Hfxt可以将执行信息发送到何处。执行完成后，可以从”执行信息视角”查看此信息。

描述

执行信息存储位置决定了 Hfxt可以将执行信息发送到何处。

执行完成后，可以从 执行信息视角 查看此信息。

选项

选项 描述 默认值
名称 此执行信息存储位置使用的名称 -
描述 此执行信息存储位置的描述 -
数据记录延迟（毫秒） 2000
数据记录间隔（毫秒） 5000
数据记录大小（行数） 1000
存储位置类型 要写入的存储位置插件类型。根据类型不同，你可以输入更多特定于插件的选项。

存储位置类型特定选项

文件存储位置

使用文件存储位置，你可以将执行信息写入本地文件系统路径中的文件。

选项：

  • 根文件夹：写入执行信息的文件夹。

缓存文件存储位置

与文件存储位置类似，执行信息被写入一个文件夹。不同之处在于，信息是按管道或工作流写入的。所需的所有信息都聚合到这些顶级JSON文件中。实现方式是将执行信息在内存缓存中保留一段可配置的时间。好处是对文件系统的压力小得多。缺点是会额外占用一些内存。例如，GUI中的某些导航操作（如查找相关执行）将需要读取更多数据。

选项：

  • 根文件夹：将执行信息存储为JSON文件的文件夹

  • 持久化延迟：这是在将执行信息写入磁盘之前等待的最长时间，以毫秒为单位。

  • 最大缓存时间：这是在清除执行信息之前，将其保留在内存中的最长时间，以毫秒为单位。建议将此时间设置为低于工作流或管道的预期持续时间。

远程存储位置

远程存储位置允许你将执行信息写入Hfxt服务器。

选项：

  • Hfxt服务器：要将执行信息写入的远程Hfxt服务器。

  • 执行信息存储位置：远程Hfxt服务器上要使用的执行信息存储位置。

Neo4j存储位置

使用此存储位置类型，你可以将执行信息存储在 Neo4j 图形数据库中。有关此插件的更多信息，请参阅 Neo4j存储位置类型 文档。

Elastic存储位置

Elastic存储位置类型将信息存储在Elastic索引中。请参阅 Elastic存储位置类型

清理

如果你想自动从图形数据库中删除执行信息，可以使用管道或工作流来实现。

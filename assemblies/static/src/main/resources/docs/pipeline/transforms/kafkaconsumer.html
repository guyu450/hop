Kafka消费者

描述

Kafka消费者转换从Kafka提取流数据。它运行一个子管道，该子管道根据消息批次大小或持续时间执行，使您能够近乎实时地处理连续的记录流。此子管道必须以注入器转换开始。您可以定义要接受处理的消息数量，以及流活动数据和系统指标的特定数据格式。您可以设置此转换来收集监控事件、跟踪用户对数据流的消耗以及监控警报。Kafka记录存储在主题中，并且包含记录发布到的类别。主题被划分为一组称为分区的日志。Kafka通过在消费者组之间分配分区来扩展主题消费。消费者组是共享一个公共组标识符的一组消费者。由于Kafka消费者转换会持续摄取流数据，您可能希望在父管道或子管道中使用中止转换，以针对特定工作流停止从Kafka消费记录。例如，您可以按定时计划运行父管道，或者如果传感器数据超过预设范围则中止子管道。

字段

选项 描述
输入名称

输入名称从Kafka流接收。默认接收以下内容：

  • 键：确定 消息到分区的分布。如果不存在键，消息将从分区中随机分布。

  • 消息：记录中包 含的单个消息。每个记录由一个键、一个值和一个时间戳组成。

  • 主题：记录发布到的类别。

  • 分区： 一个不断追加的有序记录序列。消费者数量不能超过分区数量。

  • 偏移量：Kaf ka为每个记录分配的顺序ID号。它在分区内唯一标识每个记录。

  • 时间戳：消息在服务器上接收的时间。
输出名称 “输出名称” 可以映射到订阅者和成员要求。
类型

“类型” 字段定义流记录的 数据格式。您必须选择生成记录的相同数据类型。此字段适用于 “键” 和 “消息” 输入名称。选项包括：

  • 字符串

  • 布尔值

  • 数字

  • 整数

  • 二进制

错误处理

Kafka消费者支持错误处理，但这 仅限于批次大小等于1的情况（来自Kafka队列的记录逐个处理）。在这种情况下，每当来自Kafka队列的记录在调用的子管道中产生错误时，该记录将被发送到错误路径进行进一步处理。进入错误路径的记录将在Kafka中提交，并且队列中的下一条记录可以毫无问题地进行处理。除了错误处理插入的错误字段外，流入错误路径的记录布局将是 “字段” 选项卡中指定的布局。

在任何情况下，如果Kafka队列中有一条记录阻止进一步记录的处理（因为它在处理过程中产生错误），并且我们希望将其从队列中 “移除”，以便我们可以处理队列中的其余记录，此功能都非常有用。失败的记录可以保存到某个位置（例如保存到文件或数据库表）以供进一步调查。

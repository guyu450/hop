Beam Kafka 消费

描述

Beam Kafka 消费转换使用 Beam 执行引擎从 Kafka 集群中消费记录。

限制

Kafka 消费者的主要限制是，目前它仅支持将字符串作为键，将字符串和 Avro 记录作为值进行读取。

选项

选项 描述
转换名称 转换的名称，此名称在单个管道中必须唯一。
引导服务器 以逗号分隔的主机列表，这些主机是 “引导” Kafka 集群中的 Kafka 代理。
要消费的主题 以逗号分隔的要消费的主题列表。
组 ID 指定 Kafka 消费者所属的消费者组的 ID。
键输出字段的名称 结果键字段。
消息输出字段的名称 结果消息字段。
消息类型（默认是 String） 从 Kafka 获取的消息类型。
模式注册表 URL（Avro） 如果要消费 Avro 记录消息，则为模式注册表的 URL
模式注册表主题（Avro） 模式注册表中的主题名称（模式名称）。这将使我们能够知道正在消费哪种类型的 Avro 值。
使用处理时间 记录由 Beam 处理的时间。
使用日志追加时间 记录由代理追加的时间。
使用创建时间 生产者记录创建的时间。
将读取限制为已提交的消息 将读取限制为仅已提交的记录。
允许提交偏移量 允许提交偏移量以将偏移量标记为已消费。
配置选项 配置参数列表。
参数 一个配置参数。
值 参数值。
类型 值的数据类型。

Avro 和模式注册表

以下是从 Kafka 服务器消费 Avro 记录值所需的一些选项。Avro 值的模式不会发送到 Kafka，而是发送到模式注册表。因此，你需要有一个可用的模式注册表。以下是在 Confluent Cloud Kafka 实例上使其正常工作需要设置的一些选项。软件栈的各个部分都需要进行身份验证，因此存在一些冗余。我们建议你将这些选项放在环境配置文件的变量中。

选项 示例
auto.offset.reset earliest（或 latest）
sasl.jaas.config org.apache.kafka.common.security.plain.PlainLoginModule required username="CLUSTER_API_KEY" password="CLUSTER_API_SECRET";
security.protocol SASL_SSL
basic.auth.credentials.source USER_INFO
basic.auth.user.info CLUSTER_API_KEY:CLUSTER_API_SECRET
schema.registry.basic.auth.user.info SCHEMA_REGISTRY_API_KEY:SCHEMA_REGISTRY_API_SECRET
sasl.mechanism PLAIN
client.dns.lookup use_all_dns_ips
acks ALL

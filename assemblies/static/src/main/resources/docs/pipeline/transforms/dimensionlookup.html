维度查找/更新

描述

维度查找/更新转换允许您针对两种类型（类型I（更新）和类型II（插入））实现拉尔夫·金博尔（Ralph Kimball）的缓慢变化维度，并具备一些附加功能。此转换可用于填充维度表或在缓慢变化维度中查找值而不进行任何更改。

  • 预加载缓存？在执行查找 之前读取维度表的完整内容可以提高性能。通过消除与数据 库的往返次数以及使用排序列表查找算法，性能得到提升。

技术键标签页

此标签页包含与维度记录的代理键创建相关的详细信息。

选项 描述
技术键字段 维度的主键；也称为代理键。使用”新名称”选项在查 找后重命名技术键。例如，如果您需要查找不同类型的产品 ，如ORIGINAL_PRODUCT_TK、REPLACEMENT_PRODUCT_TK等。
技术键的创建

指示 技术键的生成方式，与您的连接类型不兼容的选项将变灰：

  • 使用表最大值 + 1：将根据表中的最大键创建一个新的技术键。请注意 ，新的最大值始终被缓存，因此无需为每一行计算最大值。

  • 使用序列：如果您想在表连接上使用数据库序列生成 技术键（例如，这在Oracle中很常见），请指定序列名称。

  • 使用自动递增字段：使用数据库表 中的自动递增字段生成技术键（例如，DB2支持此功能）。

一般注意事项

作为此转换类型的查找或更新操作的结果，一个包含维度技术键的字段将被添加到流中。如果未找到该字段，则返回维度条目的”未找到”值（0或1，具体取决于数据库类型）。

一些可选字段（在”字段”标签页中）由转换自动管理。您可以在”维度字段”列中指定表字段名称。这些是可选字段：

  • 最后插入或更新日期（无流字段作为源）：添加并管理一个日期字段

  • 最后插入日期（无流字段作为源）：添加并管理一个日期字段

  • 最后更新日期（无流字段作为源）：添加并管理一个日期字段

  • 最后版本（无流字段作为源）：添加并管理一个布尔字段。（根据您的数据库连接设置和此类数据类型的可用性，转换为Char(1) 或布尔数据库数据类型）

  • 这用作最后版本的当前有效维度条目指示器：因此，当类型II属性发生变化并创建新版本（以跟踪历史记录）时，上一版本中的”最后版本”属性将设置为”False/N”，而最新版本的新记录将设置为”True/Y”。

功能

正如转换的名称所示，该转换的功能分为两类，查找和更新……

查找

在只读模式（更新选项禁用）下，转换仅在缓慢变化维度中执行查找操作。转换将在指定的数据库连接和指定的模式下的维度表中执行查找。为了进行查找，它不仅使用指定的自然键（使用”等于”条件），还使用指定的”流日期字段”（见下文）。应用的条件是：

“表日期范围起始” ⇐ “流日期字段” 且 “表日期范围结束” > “流日期字段”

如果未指定”流日期字段”，我们将使用当前系统日期来查找正确的维度版本记录。

如果未找到行，则返回”未知”键。（“未知”键将为0或1，具体取决于您是否为技术键字段选择了自动递增字段）。请注意，我们不区分”未知”、“未找到”、“空”、“非法格式”等。但是，这些细微差别可以手动添加。在数据到达此转换之前，没有什么可以阻止您使用过滤器、正则表达式等清除这些类型的数据。我们建议您为这些特殊维度条目情况手动添加值 -1、-2、-3等，就像在填充维度表之前添加”未知”行的具体细节一样。

  • 请勿在自然键中使用NULL值。NULL值无法进行比较，并且大多数数据库不会对其建立索引。即使我们支持在键中使用NULL值（这无论如何都没有太大意义），也很可能会导致严重的查找性能问题。

  • 如果输入流中的数据类型与自然键中的数据类型不同，请注意可能出现的数据转换问题。例如，如果转换输入中是字符串，而数据库中使用的是整数，请确保您能够将字符串转换为数字。将此视为最佳实践，在进行此转换之前完成，以确保其按计划工作。另一个典型的问题示例是浮点数比较。请避免使用这些。我们建议您使用合理的数据类型，如整数或长整数。避免使用双精度、十进制或像Oracle的Number（无长度或精度；它隐式使用精度38，导致我们使用较慢的BigNumber数据类型）这样的通用数据类型。

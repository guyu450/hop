数据库查找

描述

数据库查找转换允许您在数据库表中查找值。查找值会作为新字段添加到流中。

选项

选项 描述
转换名称 转换的名称。此名称在单个管道中必须唯一。
连接 到查找表的数据库连接。
查找模式 包含查找表的数据库模式。
查找表 用于查找的数据库表的名称。
启用缓存？

启用数据库查找的缓存。这意 味着一旦查找了某个键（或一组键），查找的 值就会被存储起来，下次查找这个键（或一组 键）时将再次返回（无需进行数据库调用）。

重要：如 果其他进程正在更改您执行查找的表中的值， 请不要缓存值。在所有其他情况下，缓存值会 显著提高性能，因为数据库查找相对较慢。如 果您无法使用缓存，可以考虑同时启动多个副 本。同时启动可以通过不同的连接使数据库保 持繁忙状态。请参阅”启动转换的多个副本”。
缓存行数 缓存的大小（行数），0 表示缓存所有内容。
从表中加载所有数据

用查找表中存在的所有数据预加载缓存。 这可以通过避免数据库调用提高性能。但是， 如果您的表很大，可能会有内存不足的风险。

重要：由于数据库比较数据的方式不同，内 存查找可能会导致不同的结果。例如，如果您 的数据库表允许不区分大小写的比较，使用此 选项可能会得到不同的结果。对于带有尾随空 格的数据也是如此。在某些数据库中，使用某 些字符数据类型时，这些空格会被忽略。有关 此选项的更多详细信息，请参阅下面的注释。
查找表的键

执行数据库查找的键和条件。

提示：在键查找中使用 LIKE 运算符时，它不会自动在 流值中添加通配符。因此，默认情况下，LIKE 运算符的行为类似于 "="（有关 LIKE 运算符的特定 SQL 主题，请参阅 您的数据库）。可以在数据库查找之前添加一 个”字符串替换”转换来添加通配符。在替换转 换中选择查找字段，然后使用正则表达式查找 (^.*) 并替换为 %$1%。 这将为后续的查找任务在字段中添加通配符。
返回表的值

要添加到输出流中的查找表字段。如果数据 库列名不合适，“新名称”允许您使用不同的名 称。“默认值”是查找失败时返回的值（而不是 null）。

注意事项：

  • 在数据库查找转换上启用错误 处理将把所有查找失败的行重定向到错误处理 转换，而不是将它们添加到主输出流中并带有 null/默认值。

  • 类型是输出字段的类型。

  • 当我们使用 修剪类型 选项时，当前转换 的行为是修剪所有空格，但保留转换在成功查 找时提取的字符串中最终包含的任何换行符。
查找失败时不传递该行 启用此选项可在查找失败时避免传递该行。在 SQL 语法中 ，启用此选项将是内连接，否则将是外连接。
查找返回多个结果时失败？ 启用此 选项可在查找返回多个结果时强制转换失败。
排序依据 如果查找查询返回多个结果，ORDER BY 子 句可帮助您选择要使用的记录。例如，ORDER BY 可让您在指定状态中选择销售额最高的客户。
获取字段 点击可返回转换的输入流中的可用字段列表。
获取查找字段 点击可返回查找 表中可添加到转换输出流中的可用字段列表。

关于”从表中加载所有数据”选项的说明：例如：当存储类型为”CHAR(3)“的值时，许多数据库将使用 3 个字符存储”ab”：“ab”（注意空格）。当您执行”SELECT * FROM my_lookup_table WHERE key_column = 'ab'“时，数据库很智能，在应用 where 子句之前会添加一个空格（它查找的是 'ab ' 而不是 'ab'）。

当您使用”从表中加载所有数据”预加载缓存时就会出现问题：在启动时，缓存是使用数据库中存在的所有值构建的，因此我们在缓存中存储 'ab '。后来，查找 'ab' 失败，因为在 Java 相等性比较中尾随空格很重要。

请注意，如果禁用”从表中加载所有数据”，使用缓存时不会出现此问题。实际上，对 'ab' 的第一次查找将在缓存中找不到条目，调用数据库（数据库足够智能，可以处理尾随空白问题），获取正确的结果，并将其存储在 Java 缓存中 'ab' 键下。因此，下次对 'ab' 的查找将在缓存中找到合适的结果 ：）
